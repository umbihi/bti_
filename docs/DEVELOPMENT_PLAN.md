## 2. 단계별 개발 로드맵 (Roadmap)

```
[현재 위치: Phase 0 마무리 단계 — 브라우저 CORS 최종 확인만 남음]
Phase 0: 엔진 실연동 & 0단계 품질 검증 ──> Phase 1: 클로즈드 베타 (10~20명) ──> Phase 2: 2차 고도화 기능 ──> Phase 3: 퍼블릭 런칭
```

### Phase 0: 엔진 실연동 & 0단계 품질 검증 (예정 기간: 3~5일 / 진행: 마무리 단계)
* **목표**: Mock 데이터를 브라우저 직접 Gemini API 호출 로직으로 교체하고, 가상 자소서 30건으로 판정 일관성·환각 0건·가명화 누락 0건을 통과한다.
* **주요 작업**:
  1. ✅ `lib/diagnose.ts`를 Direct REST API (`fetch`) 호출로 교체 (Google GenAI SDK 미사용)
  2. ✅ 모델 확정: `gemini-3.1-flash-lite` (기본값, 이전 후보 `gemini-2.5-flash`는 신규 사용자 404) 및 JSON 구조화 출력 강제
  3. ◐ 브라우저 CORS 및 레이턴시 벤치마크 — preflight 통과, 지연 실측 완료(p50 4.8초, 꼬리 지연 → 타임아웃 30초로 대응). **배포 URL에서의 브라우저 CORS 최종 확인 남음**
  4. ✅ 가상 자소서 30건(직군별 5건) 테스트 세트 작성 및 검증 (§5.2)

### Phase 1: 클로즈드 베타 테스트 (CBT) (예정 기간: 2주)
* **목표**: 실제 신입/이직 준비 지원자 10~20명을 대상으로 본인 무료 키 기반 실사용 검증.
* **주요 작업**:
  1. Vercel 무료 티어 배포 및 배포 URL 발급
  2. Vercel Analytics 이벤트 로깅 점검 (키 발급 완료율, 재진단율, 피드백 긍정률)
  3. 지원자 온보딩: Google AI Studio 무료 키 발급 3단계 가이드 전달
  4. 피드백 수집 및 프롬프트 미세 조정 (직군별 전문 용어 보정)
* **통과 기준**:
  - 키 연결 완료율 > 60%
  - 세션당 진단 횟수 > 2.0회
  - 피드백 긍정률 > 75%

### Phase 2: 2차 고도화 기능 개발 (예정 기간: 2주)
* **목표**: 지원자의 작성 부담을 줄이고 반복 사용성을 극대화하는 편의 기능 추가.
* **주요 작업**:
  1. **F9. 경험 키워드 기반 초안 뼈대 생성기**: 지원자의 활동/경험 키워드 3개를 입력하면 STAR 구조의 개조식 초안 가이드 생성
  2. **F10. 버전별 비교(Diff) 뷰어**: 수정 전 답변과 수정 후 답변을 문장 단위로 나란히 비교
  3. **다중 문항 일괄 관리 탭**: 한 회사당 3~4개 문항을 한 세션에서 스위칭하며 작성할 수 있는 탭 UI

### Phase 3: 퍼블릭 런칭 및 운영 최적화
* **목표**: 취업 커뮤니티 공개 배포 및 안정적 자율 운영 체제 확립.
* **주요 작업**:
  1. 커스텀 도메인 연결 및 SSL 설정
  2. CSP(콘텐츠 보안 정책) 헤더 적용 (Google API 외 외부 통신 차단)
  3. 정적 에셋 최적화 및 SEO/OG 메타 태그 최적화
  4. 운영자 유료 키 전환 검토 (무료 키 이탈률 분석 결과에 따름)

## 3. 시스템 아키텍처 및 기술 명세

### 3.1 기술 스택 명세
* **Framework**: Next.js 16.4.3 (App Router)
* **Language**: TypeScript 5.7.3
* **UI Library**: React 19.2.4, Base UI (`@base-ui/react`), Lucide React
* **Styling**: Tailwind CSS v4, tw-animate-css
* **Motion & Notification**: Framer Motion 14.7.0, Sonner (Toaster)
* **State & Storage**: React Context + Custom Hooks, `localStorage` / `sessionStorage`
* **AI Engine**: Google Gemini API (`gemini-3.1-flash-lite`, REST API 직접 호출)

### 3.2 데이터 흐름 및 아키텍처 다이어그램

```
[ 사용자 브라우저 (Client-Side Only) ]
  │
  ├─ 1. 자소서 작성 & 글자수 계산 (CharGauge)
  │
  ├─ 2. 개인정보 탐지 & 가명 치환 (mask.ts)
  │      ├─ [이름], [학교N], [연락처] 토큰화 (치환 맵 로컬 보관)
  │      └─ 주민등록번호 감지 시 ➔ 전송 원천 차단 (hasRRN)
  │
  ├─ 3. Gemini REST API 직접 전송 (https://generativelanguage.googleapis.com)
  │      ├─ Header: x-goog-api-key: {사용자 브라우저 저장 키} (환경변수 운영자 키 폴백 없음)
  │      ├─ Body: 직군/직무 프롬프트 + 가명화 텍스트 + JSON Schema
  │      └─ 운영자 서버 경유 없음 (비용 0원, 데이터 유출 0건)
  │
  ├─ 4. 응답 역가명화 (unmaskResult) & 유효성 검증
  │      └─ AI 응답 속 가명 토큰을 원래 단어로 브라우저에서 복원
  │
  └─ 5. UI 렌더링 & 게이미피케이션 동기화
         ├─ 기준표 게이지(VerdictGauge) & 근거 하이라이터
         ├─ 수정 퀘스트 체크리스트 (QuestList)
         ├─ 이전 결과 비교 ➔ 레벨업 카드 (LevelUpCard)
         └─ 일일 스탬프 기록 및 업적 달성 토스트 발송
```

### 3.3 Gemini API 직접 호출 프롬프트 및 스키마 설계
`lib/diagnose.ts`의 실제 구현을 위한 명세:

* **Endpoint**: `https://generativelanguage.googleapis.com/v1beta/models/gemini-3.1-flash-lite:generateContent`
* **Generation Config**:
  ```json
  {
    "temperature": 1.0,
    "responseMimeType": "application/json",
    "responseSchema": {
      "type": "OBJECT",
      "properties": {
        "question_intent": { "type": "STRING" },
        "criteria": {
          "type": "ARRAY",
          "items": {
            "type": "OBJECT",
            "properties": {
              "id": { "type": "INTEGER" },
              "name": { "type": "STRING" },
              "verdict": { "type": "STRING", "enum": ["sufficient", "needs_work", "insufficient", "not_applicable"] },
              "evidence": { "type": "ARRAY", "items": { "type": "STRING" } },
              "feedback": { "type": "STRING" }
            },
            "required": ["id", "name", "verdict", "evidence", "feedback"]
          }
        },
        "suggestions": {
          "type": "ARRAY",
          "items": {
            "type": "OBJECT",
            "properties": {
              "original": { "type": "STRING" },
              "suggested": { "type": "STRING" },
              "reason": { "type": "STRING" },
              "criterion_id": { "type": "INTEGER" }
            },
            "required": ["original", "suggested", "reason", "criterion_id"]
          }
        }
      },
      "required": ["question_intent", "criteria", "suggestions"]
    }
  }
  ```

## 5. 품질 보증(QA) 및 테스트 계획

### 5.1 0단계 가상 테스트 세트 (30건) 검증 매트릭스
* **구성**: 앱의 6개 직군(경영·사무, 기획·마케팅, IT·개발, 디자인, 영업·고객관리, 생산·엔지니어링) × 직군당 5건 = 총 30건 (`qa/dataset.json`)
* **테스트 케이스 구성**:
  1. *완벽한 자소서 (충분 4~5개)*: 두괄식, 정량적 성과, 직무 용어 명확
  2. *결과 나열형 자소서 (부족 2~3개)*: 구체적 행동 및 직무 연결 부재
  3. *모호한 초안 (부족 4~5개)*: 두괄식 미흡, 추상적 표현 위주
  4. *개인정보 포함 자소서*: 이름, 대학교명, 이메일, 전화번호 포함 (가명화 누락 검증용)
  5. *악의적/예외 입력*: 주민등록번호 포함 자소서(차단 검증), 한글 미달 글, 코드 조각
* **합격 기준 (Pass Criteria)**:
  - **판정 일관성**: 동일 글 3회 반복 진단 시 5개 항목 판정 일치율 **80% 이상**
  - **인용 신뢰도**: 원문에 존재하지 않는 환각 인용 **0건**
  - **가명화 무결성**: 전송문에 실명, 학교명, 연락처 노출 **0건**
  - **보안 차단**: 주민등록번호 패턴 포함 시 전송 차단율 **100%**

### 5.2 Phase 0 진행 결과 (2026-10-29)
